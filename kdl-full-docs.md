### 1. Введение

#### 1.1. Что это за система
КДЛ-оборудование — веб-приложение для учёта лабораторного оборудования и контроля сроков его поверки. Система ведёт полный жизненный цикл прибора: от поступления в лабораторию до списания.

#### 1.2. Кому предназначено
- **Лаборанты** — повседневная работа: просмотр, поверки, передачи
- **Старшие лаборанты** — расширенные права: добавление, массовые операции
- **Заведующие** — контроль своего отдела
- **Администратор** — полный доступ, настройки (см. отдельное руководство)

#### 1.3. Что можно делать
- Просматривать реестр оборудования (с фильтрами, поиском, сортировкой)
- Добавлять новые приборы (по одному или партией)
- Регистрировать поверки (быстрая и полная история)
- Отправлять на поверку и возвращать с неё
- Печатать этикетки со штрихкодами
- Экспортировать данные в Excel и PDF
- Получать напоминания о просроченных поверках

### 2. Вход в систему

#### 2.1. Открытие системы
1. Откройте браузер (Chrome, Edge, Firefox, Safari — свежие версии)
2. Введите адрес системы в адресную строку. Адрес выдаёт администратор.
3. Откроется экран входа.

> 🖼️ **Скриншот 2.1 — Экран входа**
> Снять: весь экран логина с фоном (картинка лаборатории), полями «Логин» и «Пароль» и кнопкой «Войти».

#### 2.2. Первый вход
При первом входе администратор выдаёт вам логин и разовый пароль.

1. Введите логин
2. Введите разовый пароль
3. Нажмите «Войти»
4. Система сразу попросит сменить пароль — это обязательная процедура

> 🖼️ **Скриншот 2.2 — Модалка смены пароля при первом входе**
> Снять: модальное окно «Смена пароля» с тремя полями (Текущий, Новый, Подтверждение) и списком требований к паролю.

#### 2.3. Требования к паролю
Пароль должен соответствовать политике, которую настраивает администратор. Стандартные требования:

- Минимум 8 символов
- Хотя бы одна строчная буква (a-z)
- Хотя бы одна заглавная буква (A-Z)
- Хотя бы одна цифра (0-9)
- Хотя бы один спецсимвол (!@#$%^&* и т.п.)
- Без пробелов

Проверка в реальном времени: по мере ввода пароля напротив каждого требования появляется ✅ (выполнено) или ❌ (не выполнено).

#### 2.4. Если забыли пароль
Обратитесь к администратору. Он сбросит пароль и выдаст новый разовый. При следующем входе система снова попросит сменить пароль.

#### 2.5. Выход из системы
Нажмите «Выйти» в правом верхнем углу (рядом с вашим ФИО). Сессия завершится, вы вернётесь на экран входа.

### 3. Главный экран

После входа открывается главный экран — таблица со всем оборудованием, к которому у вас есть доступ.

> 🖼️ **Скриншот 3.1 — Главный экран (полный)**
> Снять: весь экран с шапкой, тулбаром, таблицей (5–7 строк) и пагинацией внизу. Если тёмная тема — сделать скриншот в светлой.

#### 3.1. Шапка (верхняя панель)
В шапке отображается:

- Название системы «Клинико-диагностическая лаборатория учёт оборудования и его поверок»
- Кнопка свернуть/развернуть шапку (▲ Свернуть / ▼ Развернуть)
- Счётчики:
  - 🟢 В норме — поверка не скоро
  - 🟡 Скоро поверка — в течение N дней (по настройкам)
  - 🔴 Просрочены — срок истёк
  - Всего — общее количество (при наведении — детальная разбивка)
- Ваше ФИО и должность (справа)
- Кнопки: вернуться (если вы под другим пользователем), тема, пароль, выйти

> 🖼️ **Скриншот 3.2 — Шапка со счётчиками**
> Снять: верхнюю часть экрана — заголовок, 4 счётчика и правый угол с ФИО и кнопками.

#### 3.2. Тулбар (панель действий)
Под шапкой — панель с инструментами:

- **Поиск** — поле для поиска по таблице
- **Фильтр** — кнопка открытия панели фильтров
- **Сканировать** — для сканирования штрихкодов (если есть права)
- **Ещё ▼** — выпадающее меню с дополнительными действиями

Когда выбраны строки (чекбоксами), появляется панель массовых действий с кнопками «Отправить», «Вернуть», «Ответственный», «Удалить» и «Снять».

> 🖼️ **Скриншот 3.3 — Тулбар в двух состояниях**
> Снять: (а) без выбора — поиск, фильтр, Ещё; (б) с 2 выбранными строками — появляются кнопки массовых действий. Два скриншота, подписать «до» и «после».

#### 3.3. Таблица
Основная часть экрана — таблица с колонками. Стандартный набор:

| Колонка | Что показывает |
|---|---|
| ☑ | Чекбокс выбора строки |
| ID | Внутренний номер (например, P-001) |
| Тип | Пипетка, анализатор, микроскоп и др. |
| Модель | Название модели + производитель |
| Объём | Для пипеток (мкл) |
| Отдел | Где находится |
| Поверка | Дата последней поверки |
| Следующая | Дата следующей + сколько дней осталось |
| Ответственный | Кто отвечает + место хранения |
| Статус | Бейдж с цветом |
| Действия | Кнопка ⋮ для меню действий |

> 🖼️ **Скриншот 3.4 — Таблица с цветными строками**
> Снять: 6–8 строк таблицы с разными статусами (зелёные, жёлтые, красные). Должны быть видны колонки «Следующая», «Статус» и кнопка ⋮.

#### 3.4. Сортировка
Кликните по заголовку колонки — данные отсортируются по возрастанию (▲). Повторный клик — по убыванию (▼). Третий клик — сброс.

Сортировка работает по: ID, тип, модель, отдел, дата поверки, следующая дата, ответственный, статус.

#### 3.5. Пагинация (внизу)
Внизу таблицы:

- «Строк:» — выпадающий список (50 / 100 / 200 / 500 — как настроил админ)
- «← Назад» и «Вперёд →» — переход между страницами
- «Стр. X из Y» — текущая страница
- «Всего: N записей» — общее количество

> 🖼️ **Скриншот 3.5 — Пагинация**
> Снять: нижнюю полосу с выбором количества строк, кнопками ← Назад / Вперёд → и счётчиком «Всего».

#### 3.6. Тёмная и светлая темы
В правом верхнем углу шапки — кнопка 🌙/☀️. Клик переключает тему. Выбор сохраняется между сессиями.

#### 3.7. Свёртывание шапки
Кнопка ▲ Свернуть уменьшает шапку до одной строки — больше места для таблицы. Полезно на маленьких экранах.

> 🖼️ **Скриншот 3.6 — Свёрнутая шапка**
> Снять: главный экран со свёрнутой шапкой (одна строка с названием и мини-счётчиком).

### 4. Работа с таблицей

#### 4.1. Поиск
В поле «Поиск» введите что угодно:

- ID (например, P-001)
- Модель (Research Plus)
- Производитель (Eppendorf)
- Серийный номер
- Отдел
- Ответственного (например, Иванова)

Результаты обновляются автоматически через 150 мс после остановки ввода.

> 🖼️ **Скриншот 4.1 — Поиск по «Eppendorf»**
> Снять: тулбар с введённым в поиск «Eppendorf» и таблицу ниже, где отфильтрованы только Eppendorf.

#### 4.2. Фильтры
Кнопка «Фильтр» открывает панель с полями:

- Статус — все / в норме / скоро / просрочен / на поверке / брак / в процессе / неактивен
- Тип оборудования
- Отдел
- Ответственный (частичное совпадение)
- Модель
- Производитель
- Дата поверки — период (сегодня / вчера / 7 дней / 30 дней / произвольный)

Внизу панели — кнопки «Сбросить» и «Применить».

> 🖼️ **Скриншот 4.2 — Панель фильтров**
> Снять: открытую панель фильтра со всеми полями и кнопками внизу.

#### 4.3. Изменение колонок
Вы можете:

- **Перетащить колонку** — зажмите заголовок и перетащите влево/вправо
- **Изменить ширину** — потяните за правую границу заголовка
- **Скрыть/показать колонки** — через личные настройки (или настройки, которые задаёт админ)

Порядок колонок сохраняется автоматически для вашего пользователя.

> 🖼️ **Скриншот 4.3 — Перетаскивание колонки**
> Снять: момент перетаскивания (заголовок «Модель» с полупрозрачностью над колонкой «Тип», между ними подсветка).

#### 4.4. Выбор строк
- Одна строка — клик по чекбоксу в строке
- Несколько — клик по нескольким чекбоксам
- Все на странице — чекбокс в заголовке таблицы (выделяет только текущую страницу)
- Переход между страницами — выбранные строки сохраняются

В тулбаре появляется индикатор «Выбрано: N».

> 🖼️ **Скриншот 4.4 — Выбранные строки**
> Снять: 2–3 выбранные строки (с синей подсветкой) и тулбар с надписью «Выбрано: 3».

### 5. Действия с одной единицей

Кнопка ⋮ в правой колонке строки открывает меню действий.

> 🖼️ **Скриншот 5.1 — Меню ⋮**
> Снять: открытое меню действий с пунктами «Быстрая поверка», «Редактировать», «Передать», «История», «Аудит», «Удалить».

#### 5.1. Быстрая поверка
**Когда использовать:** когда прибор прошёл поверку и нужно быстро зарегистрировать результат.

1. Откройте меню ⋮ → «Быстрая поверка»
2. Введите:
   - Дата поверки (по умолчанию — сегодня, нельзя указать будущее)
   - Номер свидетельства (необязательно)
   - Результат — Годен / Брак / В процессе
   - Организация (например, ФБУ «Красноярский ЦСМ»)
   - Примечание (необязательно)
3. Нажмите «Записать»

**Что произойдёт:**

- Дата последней поверки обновится
- В таблице обновится «Следующая»
- Статус пересчитается автоматически

> 🖼️ **Скриншот 5.2 — Модалка «Быстрая поверка»**
> Снять: модалку с заполненными полями (дата — сегодня, свидетельство, результат «Годен»).

#### 5.2. Редактировать
Открывает форму редактирования. ID прибора нельзя изменить (он присвоен навсегда).

При смене типа оборудования (например, с пипетки на анализатор) ID автоматически перегенерируется (P-001 → A-001), а история поверок переедет вместе с прибором.

Подробнее — см. раздел 6.2 (создание) — форма редактирования идентична.

#### 5.3. Передать в другой отдел
Используется, когда прибор физически перемещается в другой отдел.

1. Меню ⋮ → «Передать в другой отдел»
2. Выберите новый отдел (текущий отдел не показывается)
3. Выберите ответственного в новом отделе
4. Нажмите «Передать»

Вся история поверок сохраняется.

> 🖼️ **Скриншот 5.3 — Модалка «Передача в другой отдел»**
> Снять: модалку с текущим отделом (в шапке), выпадающими списками «Новый отдел» и «Ответственный».

#### 5.4. История поверок
- Меню ⋮ → «История поверок (N)» — в скобках количество записей

Откроется модалка с:

- Карточкой прибора (модель, серийный, отдел, МПИ, статус)
- Таймлайном поверок — свежие сверху
- Кнопкой «Добавить поверку» — для ручного добавления записи
- Кнопкой «Печать истории» — экспорт в Excel/PDF

> 🖼️ **Скриншот 5.4 — Модалка «История поверок»**
> Снять: таймлайн с 2–3 записями (даты, свидетельства, результаты с цветными бейджами).

#### 5.5. Аудит изменений
Показывает, кто и когда менял прибор. Полезно, когда нужно выяснить, кто и когда изменил дату поверки.

Доступно только пользователям с правом «Аудит изменений».

> 🖼️ **Скриншот 5.5 — Модалка «Аудит»**
> Снять: список записей с датой, ФИО пользователя, действием и деталями изменений.

#### 5.6. Отменить отправку
Показывается только для приборов на поверке. Возвращает прибор в статус «в работе».

Если прибор был отправлен с заменой — замена вернётся на склад.

> 🖼️ **Скриншот 5.6 — Диалог «Отмена отправки»**
> Снять: окно подтверждения с текстом «Отменить отправку P-001 на поверку? Замена P-005 вернётся на склад».

#### 5.7. Удалить
**Когда нельзя удалить:**

- Прибор на поверке — сначала оформите возврат или отмените отправку
- Прибор используется как замена для другого — сначала верните оригинал с поверки
- За прибором закреплена замена — сначала оформите возврат

**Если удаление разрешено:**

1. Меню ⋮ → «Удалить»
2. Подтвердите — действие необратимо
3. История поверок тоже удалится

> 🖼️ **Скриншот 5.7 — Окно подтверждения удаления**
> Снять: окно с текстом «Удалить оборудование P-001 вместе со всей историей поверок? Действие необратимо» и красной кнопкой «Удалить».

### 6. Добавление оборудования

#### 6.1. Открытие формы
Кнопка «Ещё ▼» в тулбаре → «Создать оборудование».

Откроется модалка с двумя вкладками:

- «Одна единица» — форма для одного прибора
- «Партия (таблица)» — для массового добавления

> 🖼️ **Скриншот 6.1 — Модалка создания с вкладками**
> Снять: модалку с активной вкладкой «Одна единица» и видимыми вкладками сверху.

#### 6.2. Одна единица
Заполните поля:

- Внутренний номер — генерируется автоматически (можно оставить как есть)
- Модель * — обязательное
- Тип оборудования — Пипетка / Анализатор / Микроскоп и т.д.
- Серийный номер
- Производитель
- Объём — для пипеток (мкл)
- Отдел
- Ответственный
- Дата последней поверки * — обязательное
- МПИ — межповерочный интервал (мес., по умолчанию 12)
- Свидетельство — номер
- Результат — Годен / Брак / В процессе
- Статус — В работе / Не используется
- Место хранения
- Примечание

Поля с * — обязательные.

> 🖼️ **Скриншот 6.2 — Форма добавления**
> Снять: форму с заполненными полями (модель «Research Plus», тип «Пипетка», дата сегодня, объём 1000 и т.д.).

#### 6.3. Партия (таблица)
Для массового добавления похожих приборов:

1. Вкладка «Партия (таблица)»
2. Нажмите «Добавить строку» — появится пустая строка
3. Заполните ячейки (как в Excel)
4. Добавьте нужное количество строк (максимум — по настройкам админа)
5. Нажмите «Создать N единиц»

При >20 строк появится подтверждение.

> 🖼️ **Скриншот 6.3 — Вкладка «Партия»**
> Снять: таблицу с 3–4 заполненными строками, кнопкой «Добавить строку» сверху и «Создать N единиц» внизу.

#### 6.4. Штрихкод
В форме есть поле «Штрихкод»:

- **Автоматически** — генерируется из инв. номера, серийного или ID
- **Вручную** — админ может ввести своё значение
- **Сброс** — кнопка «↺» возвращает к авто

Длина штрихкода ограничена настройкой админа (стандарт — 255 символов).

### 7. Массовые операции

#### 7.1. Как выбрать несколько
1. Поставьте чекбоксы в нужных строках

### 8. Отправка на поверку

### 16. Частые проблемы

**«Нет прав на действие»**
Обратитесь к администратору — у вашей роли нет нужного права.

**«Сессия истекла»**
Нажмите OK — система вернёт вас на экран входа. Войдите заново. Если это происходит часто — возможно, администратор снизил время сессии.

**«Прибор заблокирован»**
Другой пользователь открыл прибор на редактирование. Подождите 30 минут (блокировка снимется автоматически) или обратитесь к этому пользователю.

**«Не удалось сохранить»**
Возможно, кто-то изменил данные параллельно. Ваши изменения сохранятся как черновик — при следующем открытии они подставятся в форму.

**«Сервис временно недоступен»**
Сервер перегружен или обновляется. Подождите 10–20 секунд и повторите.

**«Ошибка 500»**
Обратитесь к администратору. Он посмотрит логи и разберётся.

**Белый экран / «что-то пошло не так»**
1. Обновите страницу (Ctrl+F5)
2. Если не помогло — очистите кеш браузера
3. Если всё ещё белый — обратитесь к админу

### 1. Введение

#### 1.1. Назначение документа
Руководство описывает действия администратора по настройке и поддержке системы учёта оборудования КДЛ. В отличие от руководства пользователя, здесь акцент на конфигурации, правах, справочниках, интеграции и обслуживании.

#### 1.2. Кто считается администратором
Пользователь с ролью `admin` (или эквивалентной в вашей установке). Только администратор может:
- Создавать/удалять/редактировать пользователей
- Назначать роли и права
- Менять настройки системы (отделы, типы, МПИ, фильтры)
- Управлять интеграциями и логами
- Делать бэкапы/восстановление БД

#### 1.3. Важные ограничения
- Не удаляйте системных пользователей (например, `system`, `migration`, `backup`) — они нужны для работы фоновых процессов.
- Перед массовым импортом/экспортом справочников делайте бэкап.
- Изменения прав вступают в силу сразу при сохранении, но кэши прав в браузере могут обновляться после F5.

### 3. Управление пользователями

#### 3.1. Список пользователей
На вкладке «Пользователи» отображается таблица:

| Колонка | Описание |
|---|---|
| ID | Внутренний идентификатор |
| Логин | Для входа в систему |
| ФИО | Отображаемое имя |
| Роль | Текущая роль (с цветовым бейджем) |
| Статус | Активен / Заблокирован / Архив |
| Отдел | Привязанный отдел (если есть) |
| Дата регистрации | Когда создан аккаунт |

#### 3.2. Создание пользователя
1. Кнопка «Создать» в панели пользователей
2. Заполните:
   - Логин (уникальный, латиница, без пробелов)
   - ФИО (для отображения)
   - Email (для уведомлений, необязательно)
   - Роль (выберите из списка)
   - Отдел (при необходимости)
3. Нажмите «Создать»
4. Система сгенерирует разовый пароль и покажет его один раз — скопируйте и передайте пользователю

> 🖼️ **Скриншот 3.2 — Форма создания пользователя**
> Снять: форму с полями «Логин», «ФИО», «Роль», «Отдел» и кнопкой «Создать».

#### 3.3. Редактирование пользователя
Доступно изменение:
- ФИО
- Email
- Роли (через выпадающий список или пресет)
- Отдела
- Статуса (Активен / Заблокирован)

**Важно:** нельзя изменить логин. Если нужен другой логин — создайте нового пользователя и перенесите права/данные.

#### 3.4. Сброс пароля
1. Выберите пользователя
2. Кнопка «Сбросить пароль»
3. Система покажет новый разовый пароль — передайте пользователю
4. При следующем входе система потребует сменить пароль

#### 3.5. Блокировка и разблокировка
- **Заблокировать** — пользователь не сможет войти, но все данные и история сохраняются
- **Разблокировать** — восстанавливает доступ

Используйте блокировку при увольнении или подозрении на компрометацию.

### 14. Частые проблемы и решения

**«Пользователь не видит оборудование своего отдела»**
Проверьте:
- Привязан ли пользователь к отделу
- Назначены ли права на чтение оборудования
- Не заблокирован ли пользователь

**«Не удаётся создать пользователя — ошибка уникальности логина»**
Логин уже существует. Используйте другой или найдите существующего пользователя с этим логином.

**«Права не применяются сразу»**
Права кэшируются в браузере. Попросите пользователя обновить страницу (F5) или выйти/войти заново.

**«Бэкап не создаётся»**
Проверьте права на запись в том `backups/`. Если используется Docker, убедитесь, что том смонтирован корректно.

**«Интеграция не работает»**
Проверьте API-ключ, URL, сетевые правила и логи приложения. Для отладки используйте вкладку «Логи и аудит».

**«Фильтр по ответственным не подтягивает пользователей»**
Убедитесь, что:
- Ответственные назначены на отдел
- У пользователей есть активная роль
- Фильтр настроен корректно (не скрыт для роли пользователя)

### 1. Введение

API предназначено для интеграции внешних систем с системой учёта оборудования КДЛ. Позволяет выполнять операции с оборудованием, поверками, пользователями, справочниками, а также получать отчёты и аудит.

API построено по REST-принципам, использует JSON для передачи данных, поддерживает пагинацию, фильтрацию и сортировку.

---

### 2. Базовые требования

#### 2.1. Базовый URL
Все запросы отправляются на базовый URL:

```
https://api.kdl-equipment.local/v1
```

(в локальной среде может быть `http://localhost:3000/v1`).

#### 2.2. Методы HTTP
- `GET` — получение данных
- `POST` — создание/массовые операции
- `PUT` / `PATCH` — обновление
- `DELETE` — удаление

#### 2.3. Заголовки
Обязательные заголовки для всех запросов (кроме публичных health-check):

```http
Content-Type: application/json
Authorization: Bearer <access_token>
X-Request-ID: <uuid> (рекомендуется для трассировки)
```

---

### 3. Аутентификация и авторизация

#### 3.1. Получение токена

**Endpoint:** `POST /auth/login`

**Тело запроса:**
```json
{
  "login": "ivanov",
  "password": "StrongPass123!"
}
```

**Ответ (200 OK):**
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
  "expires_in": 3600,
  "user": {
    "id": 123,
    "login": "ivanov",
    "full_name": "Иванов И.И.",
    "roles": ["lab_assistant", "admin"]
  }
}
```

#### 3.2. Использование токена
Токен передаётся в заголовке `Authorization: Bearer <access_token>`. Срок жизни — 1 час. Для продления — используйте refresh-токен.

#### 3.3. Права доступа
Каждое действие требует соответствующего права:
- `equipment.read` — чтение оборудования
- `equipment.create` — создание
- `calibration.send` — отправка на поверку
- `user.manage` — управление пользователями

Если прав недостаточно — возвращается ошибка `403 Forbidden`.

---

### 4. Общие правила запросов и ответов

#### 4.1. Пагинация
Для списков поддерживается пагинация:

- `page` — номер страницы (по умолчанию 1)
- `per_page` — количество записей (по умолчанию 50, максимум 500)

Пример: `GET /equipment?page=2&per_page=100`

Ответ включает метаданные:
```json
{
  "data": [...],
  "meta": {
    "page": 2,
    "per_page": 100,
    "total": 1234,
    "pages": 13
  }
}
```

#### 4.2. Фильтрация и сортировка
Параметры:
- `filter[status]` — фильтр по статусу
- `filter[department]` — по отделу
- `sort` — сортировка (например, `sort=-next_calibration_date` для убывания)

#### 4.3. Обработка ошибок
Все ошибки возвращаются в едином формате:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Поле 'model' обязательно",
    "details": [
      {"field": "model", "message": "Обязательное поле"}
    ]
  }
}
```

### 5. Оборудование: CRUD и статусы

#### 5.1. Список оборудования

**Endpoint:** `GET /equipment`

Поддерживает фильтры: `filter[type]`, `filter[responsible]`, `filter[status]`, `filter[department]`.

**Пример ответа:**
```json
{
  "data": [
    {
      "id": "P-001",
      "model": "Research Plus",
      "type": "pipette",
      "serial": "SN123456",
      "department": "КДЛ-1",
      "responsible": "Петров П.П.",
      "last_calibration": "2024-10-01",
      "next_calibration": "2025-10-01",
      "status": "ok",
      "mpi_months": 12
    }
  ],
  "meta": { }
}
```

#### 5.2. Создание оборудования

**Endpoint:** `POST /equipment`

**Тело:**
```json
{
  "model": "Research Plus",
  "type": "pipette",
  "serial": "SN654321",
  "department": "КДЛ-2",
  "responsible": "Сидоров С.С.",
  "last_calibration": "2024-09-15",
  "mpi_months": 12
}
```

**Ответ:** `201 Created` + объект с `id`.

#### 5.3. Обновление оборудования

**Endpoint:** `PATCH /equipment/{id}`

Можно обновлять отдельные поля.

**Пример:**
```json
{
  "responsible": "Кузнецова К.К."
}
```

#### 5.4. Удаление оборудования

**Endpoint:** `DELETE /equipment/{id}`

Удаляет прибор и всю историю поверок. Если прибор на поверке — вернёт ошибку.

### 6. Поверки: отправка, возврат, история

#### 6.1. Отправка на поверку (массовая)

**Endpoint:** `POST /calibration/send`

**Тело:**
```json
{
  "items": [
    {"id": "P-001"},
    {"id": "P-002"}
  ],

#### 6.2. Возврат с поверки (массовый)

**Тело:**
```json
{

      "calibration_date": "2024-11-25",
      "result": "passed",
      "certificate": "С-12345"
    }
  ],
  "return_date": "2024-11-25"
}
```

#### 6.3. История поверок

**Endpoint:** `GET /equipment/{id}/calibration-history`

Возвращает таймлайн поверок с результатами, свидетельствами и организациями.

# Часть 4. FAQ — часто задаваемые вопросы

## FAQ — Часто задаваемые вопросы
### Система учёта оборудования КДЛ

Версия 1.0 · Ноябрь 2025

---

### 1. Вход и пароли

**В. Как войти в систему?**
О. Откройте адрес системы в браузере (адрес выдаёт администратор), введите логин и пароль, нажмите «Войти».

**В. Я первый раз вхожу, что делать с разовым паролем?**
О. Введите логин и разовый пароль от администратора. Система сразу потребует сменить пароль — придумайте свой, соответствующий требованиям (они показаны на экране со счётчиком выполнения). После смены вы войдёте уже под своим паролем.

**В. Забыл пароль. Что делать?**
О. Обратитесь к администратору — он сбросит пароль и выдаст новый разовый. При следующем входе система попросит установить свой.

**В. Какой пароль подойдёт?**
О. Политика задаётся администратором, стандартно: минимум 8 символов, строчная буква, заглавная буква, цифра, спецсимвол, без пробелов. Требования видны в окне смены пароля — напротив каждого загорается ✅, когда оно выполнено.

**В. Система пишет «Сессия истекла».**
О. Нажмите OK — вас вернёт на экран входа. Войдите заново. Если это происходит часто, попросите админа проверить настройку времени сессии.

**В. Админ пишет «Пароль ещё не установлен. Оставьте поле пустым.»**
О. Это норма при первом входе встроенного администратора: поле пароля оставьте пустым и нажмите «Войти» — система предложит установить пароль.

---

### 2. Таблица и поиск

**В. Не могу найти прибор.**
О. Проверьте: (1) активен ли фильтр — кнопка «Фильтр» → «Сбросить»; (2) поле поиска — очистите его; (3) свой отдел — если включено «Показывать только свой отдел», вы не видите приборы других отделов. Проверьте статус: приборы «неактивен» и «брак» по умолчанию могут не попадать в счётчик «В норме».

**В. Как отсортировать таблицу?**
О. Клик по заголовку колонки — сортировка по возрастанию, повторный — по убыванию, третий — сброс.

**В. Как поменять колонки местами или скрыть лишние?**
О. Зажмите заголовок колонки и перетащите; ширину меняйте потягиванием за границу заголовка. Порядок сохраняется автоматически для вашего пользователя. Набор видимых колонок настраивается в личных настройках либо админом.

**В. Выбор строк слетает при переходе на другую страницу.**
О. Это не так — выбор сохраняется между страницами. В тулбаре видно «Выбрано: N». «Выбрать все» в заголовке выделяет только текущую страницу.

**В. Что означают цвета строк?**
О. Зелёный — поверка в норме; жёлтый — скоро поверка (в пределах порога дней); красный — просрочена; тёмно-красный — брак; синий — на поверке; светло-жёлтый — результат «в процессе»; серый — не используется или дата не задана. Точную расшифровку см. в Приложении Б руководства пользователя.

**В. Таблица пустая, хотя приборы есть.**
О. Скорее всего, наложился фильтр (например, автофильтр по дате после возврата с поверки). Кнопка «Фильтр» → «Сбросить».

---

### 3. Поверки

**В. Как быстро записать результат поверки?**
О. Меню ⋮ в строке прибора → «Быстрая поверка». Заполните дату, при необходимости свидетельство, организацию, примечание, выберите результат и нажмите «Записать». Дату следующей поверки и статус система пересчитает сама.

**В. Можно указать будущую дату поверки?**
О. Нет, дата поверки не может быть в будущем — система не примет.

**В. Что такое МПИ?**
О. Межповерочный интервал в месяцах. По нему считается дата следующей поверки. По умолчанию 12 мес., для каждого типа оборудования задаётся своё значение по умолчанию.

**В. Как посмотреть историю прибора?**
О. Меню ⋮ → «История поверок (N)». Внутри — карточка прибора, таймлайн записей (свежие сверху), кнопки добавления записи и печати.

**В. Кто и когда менял прибор — где посмотреть?**
О. Меню ⋮ → «Аудит изменений» (нужно право «Аудит»). Общий журнал всех действий — в «Ещё ▼» → «Журнал действий».

**В. Что делать, если прибор в браке?**
О. Статус «брак» ставится по результату поверки «Брак». Прибор выводится из работы: либо списывается (удаление — с оформлением по правилам лаборатории), либо ждёт ремонта и повторной поверки.

---

### 4. Печать и экспорт

**В. PDF открылся, но печатать не предлагает.**
О. В части документов окно открывается с готовой формой — запустите печать вручную через Ctrl+P (или правой кнопкой → «Печать»). Это нормальное поведение.

**В. Браузер блокирует окно печати.**
О. Разрешите всплывающие окна для адреса системы. Система подскажет сообщение «Разрешите всплывающие окна» — после разрешения повторите действие.

**В. Почему в PDF-документе нет строки, которую я вижу в таблице?**
О. Состав колонок в печатных документах задаёт администратор (Настройки → Печать документов). Попросите админа добавить нужное поле, либо проверить, не отключён ли документ.

**В. Экспорт в Excel не работает / файл пустой.**
О. Администратор может отключить экспорт реестра или истории (Настройки → Печать документов). Также проверьте, что таблица отфильтрована так, как нужно — в Excel уйдут данные по текущему фильтру.

**В. Как распечатать этикетки?**
О. Выберите приборы чекбоксами (или «весь фильтр»), «Ещё ▼» → «Печать этикеток». Выберите принтер (PDF A4 — универсальный вариант: скачается файл, который можно печатать на обычном принтере), количество копий и запустите.

**В. Этикетка печатается «крякозябрами» вместо русских букв.**
О. Попросите администратора проверить шрифт штрихкодов (Настройки → Штрихкоды) — нужен шрифт с поддержкой кириллицы, например DejaVu.

---

### 5. Импорт

**В. Какой формат файла нужен?**
О. .xlsx (Excel), .csv, .json или .txt. Старый формат .xls не поддерживается — пересохраните файл как .xlsx.

**В. Импорт пропускает все строки.**
О. Проверьте заголовки колонок: система распознаёт их по названию («ID», «Модель», «Серийный», «Отдел», «Дата поверки», «МПИ» и т.п.). Если заголовки другие — переименуйте. Также проверьте формат дат.

**В. Даты распознались неправильно.**
О. Стандартный формат — ДД.ММ.ГГГГ (21.10.2024). Американский ММ/ДД/ГГГГ система не угадывает — приведите даты к ДД.ММ.ГГГГ до импорта.

**В. Что значит «пропущено N строк»?**
О. Эти строки не добавлены. Типичные причины: пустая модель, некорректная дата, дубли ID (такой ID уже есть), превышение допустимой длины поля. Детали — в отчёте импорта.

---

### 6. Ошибки и странности

**В. «Прибор заблокирован: Иванов И.И.»**
О. Кто-то открыл прибор на редактирование. Подождите (блокировка снимается автоматически через 30 минут) или свяжитесь с этим пользователем.

**В. «Не удалось сохранить» / «Запись была изменена другим пользователем».**
О. Пока вы редактировали, кто-то сохранил изменения. Обновите страницу — ваш черновик подставится в форму, внесите изменения поверх свежих данных.

**В. «Нет прав на действие».**
О. У вашей роли нет нужного права. Обратитесь к администратору — он добавит право роли или выдаст персональное дополнительное право.

**В. «Сервис временно недоступен».**
О. Сервер перегружен или перезапускается. Подождите 10–20 секунд и повторите.

**В. Белый экран.**
О. Нажмите Ctrl+F5 (жёсткое обновление). Не помогло — очистите кеш браузера. Всё ещё белый — обратитесь к администратору.

**В. Напоминание о просроченных поверках показывается каждый день.**
О. Кнопка «Понятно» скрывает окно до следующего дня, «Позже» — до следующего входа. Если напоминания не нужны вовсе — администратор может их отключить для вашей роли (Настройки → Уведомления).

---

### 7. Вопросы администратора

**В. Не удаляется отдел / тип оборудования.**
О. Он используется приборами. Переведите приборы в другой отдел (или смените тип), затем удалите.

**В. Как сбросить пароль админа, если он потерян?**
О. Через БД: обнулите пароль и включите флаг обязательной установки — пользователь admin при следующем входе с пустым паролем установит новый:
```sql
UPDATE users SET password = '', must_set_password = 1 WHERE login = 'admin';

# Часть 5. Структура проекта

## Структура проекта — Система учёта оборудования КДЛ

### 1. Общая карта проекта

Проект — SPA на Vue + Node.js API + MySQL 8.0, деплой через docker-compose.

**Ключевые потоки:**
- Пользователь → Nginx → Node.js (API или SPA fallback) → MySQL.
- Статика и скриншоты — в `frontend/public` и `docs/screenshots`.
- Логи и дампы БД — вне контейнера (тома `logs/`, `backups/`).

**Стек:**
- Frontend: Vue 3, Pinia, TypeScript, Vuetify/Tailwind (по выбору), UI-тесты.
- Backend: Node.js, Express, asyncHandler-обёртка, middleware аутентификации и прав.
- БД: MySQL 8.0, пул соединений, идемпотентная схема, seed-данные.
- Инфраструктура: docker-compose, graceful shutdown, планировщик задач.

### 2. Backend — Node.js + Express

#### Папки и ключевые файлы

- `routes/` — роуты API:
  - `auth.js` — вход, смена пароля, impersonation.
  - `import.js`, `export.js` — импорт/экспорт.
  - `barcodes.js`, `barcode-printers.js` — штрихкоды и принтеры.
  - `help.js`, `view-templates.js`, `equipment-templates.js` — справочные данные и шаблоны.
- `db/` — работа с БД:
  - `pool.js` — пул соединений; контроль `FOREIGN_KEY_CHECKS`.
  - `schema.js` — `initSchema()`: создание таблиц, колонок, индексов; идемпотентно.
  - `seed.js` — начальные данные: админ, роли, отделы, демо-пипетки, help-docs.
  - `index.js` — экспорт `pool`, `query`, `getConnection`, `safeParse`, `generatePipetteId`.
- `middleware/` — перехватчики:
  - `auth.js` — проверка сессии, валидация прав, обработка `must_change_password`.
  - `wrapRouter.js` — обёртка всех async-роутов в `asyncHandler` (защита от unhandled rejection).
- `utils/` — утилиты:
  - `cleanup.js` — планировщик (например, очистка `audit_log` раз в сутки).
  - `graceful-shutdown.js` — обработка SIGTERM/SIGINT, закрытие сервера и пула за 10 сек.

#### Важные особенности

- **SPA-fallback**: всё, что не `/api/*` и не `/help-defaults/*`, отдаёт `frontend/index.html`.
- **Ожидание БД**: при старте делается до 90 попыток подключения (с интервалом 2 сек).
- **Генерация ID пипеток**: `generatePipetteId()` — единый источник истины.
- **Поиск**: колонка `search_text` в `pipettes` (CONCAT_WS) — при добавлении полей для поиска обновляй эту колонку в `ensureColumns`.
